# Enterprise Supply Chain Management

Java 21 / Spring Boot 3 microservices with a React + TypeScript console. This repository is a runnable platform foundation: service boundaries, secure API defaults, database migrations, local dependencies, CI, and representative identity, catalog/inventory, order, and shipment workflows are included. It is not a claim that every enterprise workflow, external integration, or production operational control is finished; see [docs/architecture.md](docs/architecture.md) and [docs/roadmap.md](docs/roadmap.md).

## Architecture

The edge gateway is the sole browser entry point. Independently deployable services own their persistence and expose versioned `/api/v1` contracts. Events are versioned and carry unique IDs. The local profile uses one PostgreSQL server with a separate database per service, Redis, and single-node Kafka in KRaft mode. Production deployments should use managed PostgreSQL, Redis, Kafka, TLS termination, centralized secret storage, and externally managed RSA keys.

| Component | Port | Responsibility |
|---|---:|---|
| Edge gateway | 8080 | Routing, Redis-backed request throttling, correlation IDs |
| Identity | 8081 | Users, RBAC, access JWTs, rotating refresh tokens |
| Supply | 8082 | Suppliers, products, stock and purchase orders |
| Commerce | 8083 | Customer orders |
| Logistics | 8084 | Shipments and tracking |
| Insights | 8085 | Reporting and forecast API foundation |
| Notifications | 8086 | Notification API foundation |
| Frontend | 80 | React SPA served by Nginx |

## Run locally

Prerequisites: JDK 21, Maven 3.9+, Node.js 20+, npm, Docker Desktop with Compose.

1. Copy `.env.example` to `.env` and change every local-only credential before sharing the environment.
2. Run `.\scripts\generate-dev-keys.ps1` once (requires OpenSSL).
3. Run `docker compose up --build`.
4. Open `http://localhost:3000` for the console, `http://localhost:8080` for the API gateway, `http://localhost:9090` for Prometheus, or `http://localhost:3001` for Grafana.
5. Service API documentation is available on each service at `/swagger-ui.html` when accessed directly.

For a fast compile check without Docker, run `mvn -B verify`; run the frontend checks with `npm --prefix frontend ci` and `npm --prefix frontend run build`.

The local signing key is generated by `scripts/generate-dev-keys.ps1` and must never be reused in a deployed environment. The private key is mounted only into identity; other services receive the public key. Do not commit secrets. Set `JWT_PRIVATE_KEY_LOCATION` and `JWT_PUBLIC_KEY_LOCATION` to secret-mounted key paths in production.

## API and security

All business APIs are under `/api/v1`; future breaking changes belong under `/api/v2`. Use bearer access tokens returned from `/api/v1/auth/login`; refresh tokens are opaque, stored only as SHA-256 hashes, one-time rotated, and returned only at issue time. Roles are `ADMIN`, `SUPPLIER`, `PROCUREMENT_MANAGER`, `WAREHOUSE_MANAGER`, `SALES_MANAGER`, and `LOGISTICS_MANAGER`. Stateless APIs disable CSRF; browser sessions are not used. CORS origins are explicit. Health and OpenAPI are public; all business endpoints require a valid signed JWT. The gateway adds a correlation ID and applies a Redis token bucket.

## Repository map

- `backend/` Maven reactor, shared API/error/security contracts, independently packaged Spring services.
- `frontend/` React, TypeScript, Tailwind CSS.
- `database/` per-service Flyway migrations and local database bootstrap.
- `infrastructure/` Docker Compose, Nginx, Prometheus and Grafana configuration.
- `scripts/` local developer-key generation and utilities.
- `shared-contracts/` versioned event/API contract documentation.
- `tests/` cross-service workflow test guidance.
- `docs/` architecture, operations, security notes, and staged implementation roadmap.

## CI and operations

GitHub Actions builds the Maven reactor and frontend on pushes and pull requests. Services expose Spring Boot Actuator health and Prometheus metrics at `/actuator/prometheus`. Prometheus and Grafana are included for local development. Configure tracing export, alerting, log retention, backups, disaster recovery, and deployment-specific resource policies before production use.
